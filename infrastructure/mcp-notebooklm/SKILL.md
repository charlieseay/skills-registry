# NotebookLM MCP

The `notebooklm` MCP server (proxy name `notebooklm`, installed via uv at
`/Users/charlieseay/.local/share/uv/tools/notebooklm-mcp-cli/bin/notebooklm-mcp`)
bridges **Google NotebookLM** to the Model Context Protocol. NotebookLM is
Google's AI research tool that turns documents, notes, and links into
**interactive audio notebooks** — it generates podcast-style audio summaries,
fact-checking, and Q&A from your source materials.

**Status:** This is a **community-maintained reverse-engineered tool**, not an
official Google integration. Google does not publish a public API for
NotebookLM; this MCP uses undocumented patterns. It works, but **may break if
Google changes their internal APIs**. Use for experimentation; don't rely on
it for production workflows.

**Auth:** Requires **Google account + NotebookLM access**. The server prompts
for OAuth on first use (via browser login); subsequent runs use stored credentials.

## What NotebookLM does

1. **Upload sources** — documents (PDF, DOC), notes (text, Markdown), or URLs
2. **Generate audio** — NotebookLM synthesizes a **podcast** (two AI voices
   having a conversation) about your sources
3. **Create a notebook** — organized, searchable, interactive in the NotebookLM web UI
4. **Extract insights** — key points, Q&A, fact-checks, all generated by Claude (NotebookLM uses Claude under the hood)

This MCP wraps those capabilities so agents can create notebooks & retrieve audio.

## Tool catalog (estimated 3–5 tools; exact count uncertain due to reverse-engineering)

**Likely tools (based on notebooklm-mcp-cli source patterns):**

- `create_notebook(name, description)` → create a new NotebookLM notebook
  - Returns notebook ID for further operations
  
- `upload_source(notebook_id, source_type, source_data)` → add a source (document/URL/text)
  - `source_type`: "document", "url", "text"
  - `source_data`: file path, URL, or raw text
  - Returns source ID or confirmation
  
- `generate_podcast(notebook_id)` → synthesize audio from notebook sources
  - Returns audio URL (MP3 or stream link)
  - Processing is asynchronous; may take 30–60 seconds
  
- `get_notebook(notebook_id)` → fetch notebook details (title, sources, audio status)
  
- `list_notebooks()` → list all your NotebookLM notebooks

**CAVEAT:** This list is educated guessing. The official Google API does not
exist; the actual tools may differ from what's listed. Call `tools/list` via
the MCP proxy to see the real tool set.

## Critical issues & limitations (2026-09-30)

**1. Reverse-engineered API — may break without notice**
- Google does not publish a public NotebookLM API.
- This MCP uses **undocumented patterns** (likely browser automation or
  reverse-engineered internal endpoints).
- **Risk:** If Google changes their backend, the MCP stops working. No version
  control, no SLA, no support from Google.
- **Mitigation:** Treat as experimental. For production, use NotebookLM web UI
  directly or wait for official API.

**2. OAuth login is interactive**
- First use prompts for browser-based Google OAuth.
- **Non-interactive mode:** If you need this in a CI/CD pipeline or headless
  server, you must pre-authenticate in an interactive session first.
- Credentials are stored locally (encrypted or plaintext, depending on the
  tool's security model — check source).

**3. Audio generation is asynchronous and slow**
- `generate_podcast()` doesn't return audio immediately.
- NotebookLM's servers process your notebook (extract facts, generate script,
  synthesize two AI voices).
- **Typical latency:** 30–120 seconds for a small notebook.
- **Tool behavior unknown:** Does it poll? Block? Return a job ID? Unknown.
  Check the source code or test it live.

**4. Audio format and quality are unknown**
- Exact audio codec (MP3, WAV, OGG?) is unspecified.
- Voice quality, language support, and customization options are unclear.
- **Assumption:** English, two voices (AI speakers), suitable for web playback.

**5. No notebook privacy or sharing control via MCP**
- The MCP creates notebooks in your Google account.
- Sharing, permissions, and visibility are likely managed only via the
  NotebookLM web UI.
- **Consequence:** Notebooks created by the agent are private to your Google
  account; you can't programmatically change access.

**6. Quotas and rate limits are unknown**
- Google may rate-limit notebook creation or audio generation.
- No documented limits; you'll discover them by hitting them.
- **No retry logic:** If you hit a quota, the MCP fails and you must wait.

**7. Source upload size limits are unspecified**
- Document file size, URL count, and text length limits are not published.
- **Assumption:** Similar to NotebookLM web UI (typically 50–100 MB total,
  configurable).
- If you exceed limits, upload will fail silently or with vague errors.

**8. Podcast customization is likely unavailable**
- The MCP probably only triggers the default podcast generation (two AI voices).
- Voice choice, tone, pacing, and script customization are likely web-UI-only
  features.

## Comparison: NotebookLM vs. open-notebook MCP

| Feature | NotebookLM | open-notebook |
|---------|-----------|---------------|
| **Data source** | Google Docs, PDFs, URLs, text | Local Obsidian vault notes |
| **Processing** | Google's Claude-powered AI | Local knowledge base (no AI) |
| **Audio generation** | Yes (podcast synthesis) | No |
| **Interactive UI** | Web-based NotebookLM site | None (CLI/MCP only) |
| **Privacy** | Google account, cloud-stored | Local filesystem only |
| **Reverse-engineered** | Yes, unstable API | No, reads local files |

Use **NotebookLM** for turning external sources into podcasts. Use
**open-notebook** for searching your vault without sending data to external services.
